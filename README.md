# dps_slam_docker

Docker + colcon workspace for [**DPS-SLAM**](https://github.com/perezsaura-david/dps_slam) with
two SLAM front-ends side by side: Struct SLAM and axial landmarks. This repo provides the container
and a vcstool manifest that assembles the whole workspace, so anyone can reproduce the same
development environment.

The image is ROS 2 Humble (AeroStack2 nightly) + Gazebo Harmonic, with g2o and ceres from apt
and the python stack of the REMIND re-identification tracker. The packages are pulled as source by
`vcs import` and built in-container by colcon.

## Contents

| File | Purpose |
|------|---------|
| `dockerfile` | The image: base `aerostack2/nightly-humble`, Gazebo Harmonic, dev tooling, g2o/ceres, torch/REMIND deps. Self-contained (base image + `git clone`s, no local `COPY`). |
| `docker-compose.yml` | Runs the container, bind-mounts `workspace/`, `content/`, `rosbags/` and the REMIND checkout. |
| `dps_slam.repos` | vcstool manifest: `dps_slam`, `dps_slam_msgs`, `struct_slam`, `axial_landmarks`, `remind_detector`, `livox_laser_simulation_gz`. |
| `launchers/` | tmuxinator session, config and rviz layout for Struct SLAM. |

The axial-landmark packages (detector, tracker, SLAM bridge, sim, evaluation, launch files) live in
[axial_landmarks](https://github.com/VidValda/axial_landmarks); see its README.

## Prerequisites (host)

- Docker + Docker Compose v2
- [`python3-vcstool`](https://github.com/dirk-thomas/vcstool): `sudo apt install python3-vcstool`
- [NVIDIA Container Toolkit][nvidia-toolkit] for GPU inference in `remind_detector`; enable it
  with `runtime: nvidia` (commented in the compose file, or set it in the override)
- An X server (`$DISPLAY` / `$XAUTHORITY` set) and a running SSH agent (`$SSH_AUTH_SOCK`, forwarded
  into the container for git and used by `vcs import` for the private repos)
- GUI access for the root container, once per login session: `xhost +SI:localuser:root`
- A checkout of the REMIND tracker next to this repo (`../remind-reid-tracker`, override with
  `REMIND_DIR`) if you run `remind_detector`

## Reproduce

```bash
git clone -b dev/axial_slam git@github.com:perezsaura-david/dps_slam_docker.git
cd dps_slam_docker

# 1. Assemble the workspace source.
mkdir -p workspace/src
vcs import workspace/src < dps_slam.repos

# 2. Build the image and start the container (workspace/ is bind-mounted live).
docker compose build
docker compose up -d
docker exec -it dps_slam bash

# 3. Inside the container, build the workspace.
cd /root/workspace
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
```

### GPU

torch is installed from an explicit CUDA build, selected with build args (defaults in
`docker-compose.yml`). Pick a build that supports your GPU from the
[PyTorch version table](https://pytorch.org/get-started/previous-versions/), e.g.:

```bash
TORCH_VERSION=2.7.1 TORCHVISION_VERSION=0.22.1 TORCH_CUDA=cu128 docker compose build
TORCH_CUDA=cpu docker compose build   # no GPU
```

## Notes

- `workspace/` is gitignored: `workspace/src` is generated by `vcs import` and built by colcon.
  Override its location with `WORKSPACE_DIR`.
- Rosbags are not kept in git: put them in `rosbags/` (or point `ROSBAGS_DIR` elsewhere), or
  read them from `/media`.
- Personal mounts and settings (dev configs, editor/agent state) go in an untracked
  `docker-compose.override.yml`, which `docker compose` merges automatically.
- `ros-humble-mavros` / `ros-humble-mavros-extras` are currently only published in the
  `ros2-testing` channel of packages.ros.org, so the dockerfile installs them from there (testing
  is enabled for that install only). Once they are back in the main channel that step can go back
  to a plain `apt-get install`. mavros is only needed by the AS2 MAVLink platform (real PX4
  drones), not by the SLAM pipeline.
